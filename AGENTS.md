# Library Workspace: instructions for agents

Library is a local web app that indexes Claude Code and Codex transcripts from several accounts into one project-grouped workspace, and runs both CLIs from it. A Python server in `app/` serves a React client on `127.0.0.1:8744`.

## Read first

Read `prompts/README.md` and the four always-on prompts it lists before you change anything: `prompts/orchestrator.md`, `prompts/workspace-structure.md`, `prompts/verification.md` and `prompts/safety.md`. The roles in `agents/` say which agent does what. The rules below are specific to this repository.

## Layout

| Path | Contents |
| --- | --- |
| `desktop/` | regular Library Code source export, upstream pin and patch; see desktop/docs/build-and-update.md |
| `app/*.py` | server, agent broker, transcript indexer, account and host adapters |
| `app/workbench/src/` | browser client source (React, Dockview, Monaco), with `*.test.ts` unit tests |
| `app/web/` | built client and a redirect page; generated by the build |
| `app/vscode-library/` | VS Code extension |
| `app/project-map/` | read-only project graph |
| `app/data/` | the user's private state; only `config.example.json` is tracked |
| `prompts/`, `agents/` | general agent rules and roles |
| `docs/` | onboarding, release checks, screenshots |
| `scripts/` | release packager with privacy scan |
| `scripts/harness/` | agent harness scripts and their tests |

## Run and test

```sh
./install.sh --no-refresh            # private config, session hooks, helper skill
python3 app/pipeline.py --parse-only # import transcripts, no model calls
./run.sh                             # start or open the server
cd app/workbench && npm ci && npm test && npm run build
python3 app/doctor.py                # configuration and indexing check
```

Before a release or a push, run `python3 scripts/package_workspace.py --output <new-folder>` and follow `docs/RELEASE.md`.

## Rules

- **Read `prompts/` before changing anything,** and follow `CONTRIBUTING.md` for every change.
- **Parity.** A UI change in `app/workbench/src/` also goes to `app/vscode-library/media/` where that client has the same surface. Rebuild and commit `app/web/` with the source change; never edit it by hand.
- **Never commit data.** Transcripts, `app/data/` (except `config.example.json`), account files, logs and screenshots of real chats stay out of Git. Tests and screenshots use synthetic data.
- **Model menus are generated** from the provider catalogs in code. Never hard-code a model name in the UI.
- **Running work.** Before restarting the server, check `/api/runs` and the journals in `app/data/execution/`; wait while a run is active. Never stop, resume or message a running chat, and never send a paid message as a test.
- **Projects.** Refresh with `python3 app/pipeline.py --parse-only`; it writes `app/data/classification-review.json` (also `python3 app/project_review.py`). Manual placements always win: never run `python3 app/classify.py --all`. Grouping rules and project names live in the user's `app/data/config.json`; see `docs/AGENT-ONBOARDING.md`, "Keep the project taxonomy current".
